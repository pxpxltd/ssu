  <name>Task 1: Add ResetHard to GitService interface and implementations</name>
  <files>internal/git/git.go, internal/git/exec.go, internal/git/mock.go</files>
  <action>
    Add `ResetHard` to the GitService interface, ExecGit, and MockGitService following the established 4-file pattern.

    **In `internal/git/git.go`:**
    Add to the GitService interface under the "Mutating operations" section, after `MergeAbort`:
    ```go
    ResetHard(ctx context.Context, dir, ref string) error
    ```
    This returns just `error` (no result type), matching the `MergeAbort` pattern -- `git reset --hard` is a simple pass/fail operation.

    **In `internal/git/exec.go`:**
    Add the production implementation after the `MergeAbort` method (around line 405):
    ```go
    func (g *ExecGit) ResetHard(ctx context.Context, dir, ref string) error {
        _, _, err := g.run(ctx, dir, g.Timeouts.Default, "reset", "--hard", ref)
        return err
    }
    ```
    This follows the exact same pattern as `MergeAbort` -- simple 3-line method, uses `g.Timeouts.Default`, discards stdout/stderr (errors are captured in the `GitError` type by `g.run`).

    **In `internal/git/mock.go`:**
    Add field to the MockGitService struct:
    ```go
    ResetHardFn func(ctx context.Context, dir, ref string) error
    ```
    Add method:
    ```go
    func (m *MockGitService) ResetHard(ctx context.Context, dir, ref string) error {
        if m.ResetHardFn != nil {
            return m.ResetHardFn(ctx, dir, ref)
        }
        return nil
    }
    ```

    The compile-time check in `mock_test.go` (`var _ git.GitService = (*git.MockGitService)(nil)`) will automatically verify the mock satisfies the updated interface.

  <name>Task 2: Wire rollback command with git callbacks and results table</name>
  <files>internal/cli/rollback.go, internal/backup/backup_test.go</files>
  <action>
    Rewrite `cli/rollback.go` to replace the stub at lines 97-102 with a fully wired rollback command.

    **Rewrite `runRollback` function in `internal/cli/rollback.go`:**

    The existing code up to and including the dry-run check (lines 34-95) stays mostly the same. Replace lines 97-102 (the stub) with the full wiring. The complete flow is:

    1. **Resolve project root** using `detectProjectRoot()` (from root.go).
    2. **Create GitService** using `git.NewExecGit()`.
    3. **Collect previous SHAs** before rollback (for the results table "previous SHA" column). Iterate backup submodule paths, call `gitSvc.CurrentSHA` on each `filepath.Join(projectRoot, path)`. Store in a `map[string]string` (path -> previous SHA). Errors are non-fatal (store empty string).
    4. **Interactive confirmation** (TTY only): If stdout is a TTY and `--auto` is not set, prompt "Restore N submodule(s) from this backup? [y/N]: " using `bufio.Scanner` on `os.Stdin` (matching init.go pattern). If not confirmed, return nil with info message.
    5. **Build closure callbacks** that adapt GitService methods to backup package function signatures:
       - `getCurrentStates`: Iterate paths, call `gitSvc.CurrentSHA` and `gitSvc.CurrentBranch` with `filepath.Join(projectRoot, p)`, return `map[string]backup.SubmoduleState`.
       - `gitCheckout`: Call `gitSvc.Checkout(ctx, filepath.Join(projectRoot, dir), branch)`, return error only.
       - `gitResetHard`: Call `gitSvc.ResetHard(ctx, filepath.Join(projectRoot, dir), sha)`, return error only.
       - **Critical**: The backup package passes relative paths (e.g., `plugins/auth`). The closures MUST join with `projectRoot` before calling ExecGit.
    6. **Resolve backup directory** using `resolveBackupDir(cmd)` for the safety backup location.
    7. **Call `backup.Rollback()`** with opts and the three callbacks.
    8. **Display safety backup info**: If `result.SafetyBackupFile` is non-empty, print it with `p.Info`.
    9. **Display results table** using lipgloss/table (matching the update.go dry-run pattern):
       - Headers: "Path", "Branch", "Previous", "Restored", "Status"
       - For each `result.Submodules` entry: path, branch, previous SHA (from step 3, truncated to 7 chars), target SHA (truncated to 7), status ("restored" or error message).
       - Use `tui.HeaderStyle` for header row styling, `lipgloss.NormalBorder()`, width 120.
       - Color status column: green for success, red for error.
    10. **Print summary line**: "Restored N/M submodule(s)" using `p.Success` or `p.Warning` based on whether all succeeded.

    **Required imports** for the rewritten `rollback.go`:
    - `"bufio"`, `"context"`, `"fmt"`, `"os"`, `"path/filepath"`, `"strings"`
