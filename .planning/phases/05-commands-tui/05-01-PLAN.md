<task type="auto">
  <name>Task 2: Implement status command with lipgloss/table and JSON output</name>
  <files>internal/cli/status.go</files>
  <action>
  Replace the stub in `internal/cli/status.go` with a fully working status command.

  **RunE logic (mode branching pattern from RESEARCH.md):**
  1. Get project root via `os.Getwd()` (Phase 4 config will replace this later -- for now use cwd)
  2. Create engine: `eng := engine.New(git.NewExecGit())`
  3. Read `--jobs` from persistent flags (root command defines it): `jobs, _ := cmd.Flags().GetInt("jobs")`
  4. Build `ScanOpts{RootDir: cwd, Concurrency: jobs}` -- no skip list or branch opts yet (Phase 4 config will provide those)
  5. Call `eng.Scan(cmd.Context(), opts)` -- get `*ScanResult`
  6. If `--json` flag: call `printStatusJSON(cmd.OutOrStdout(), result)` and return
  7. Otherwise: call `printStatusTable(cmd.OutOrStdout(), result)` and return

  **printStatusTable function:**
  - Import `github.com/charmbracelet/lipgloss/table` and `github.com/charmbracelet/lipgloss`
  - Import `internal/cli/tui` for StyleForStatus and style constants
  - Create table with headers: "Path", "Branch", "Target", "Behind", "Feature", "Status"
  - Use `lipgloss.NormalBorder()` for border style
  - Set `BorderHeader(true)`, `BorderColumn(true)`
  - Get terminal width: use `lipgloss.Width()` or a reasonable default (120). Note: lipgloss v1.0.0 does not auto-detect terminal width -- use a hardcoded default or os-level detection. Use `golang.org/x/term` if available, otherwise default to 120.
    - Actually, avoid adding another dep. Just default to 120 columns. The table will adapt.
  - Root row first (if result.Root != nil): path "(root)", currentBranch, targetBranch, commitsBehind, "" (no feature flag), PrimaryStatus()
  - Then submodule rows sorted by path (already sorted from engine): path, currentBranch, targetBranch, commitsBehind, "Yes"/"No" for IsFeature (detect: currentBranch != targetBranch and currentBranch is not in default priority list), PrimaryStatus()
  - `StyleFunc` callback: header row uses HeaderStyle (bold). Row 0 (root) uses RootPathStyle on Path column. Status column uses `tui.StyleForStatus(status)` per row.

  NOTE on SubmoduleInfo.IsFeature: This field does not exist on SubmoduleInfo in types.go. Feature branch detection logic: a submodule is on a feature branch if its CurrentBranch is not empty, not detached, and not in the standard priority list (develop, master, main). Implement this inline in the status command for now -- check if CurrentBranch is not in {"develop", "master", "main"} and not empty and not detached.

  **printStatusJSON function:**
  - Define `StatusJSON` struct with `Root *SubmoduleJSON`, `Submodules []SubmoduleJSON`, `ScannedAt string`
  - Define `SubmoduleJSON` struct with json tags: path, current_branch, target_branch, commits_behind, commits_ahead, is_feature, statuses ([]string), has_changes, changelog
  - Marshal with `json.NewEncoder(w).SetIndent("", "  ")` and `Encode`
  - ScannedAt uses `time.Now().Format(time.RFC3339)`

  **Important:** When --json is used, do NOT import/use lipgloss at all for the output path. Just plain JSON to stdout.
  </action>
