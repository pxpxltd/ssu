  Replace the stub in `internal/cli/push.go` with a working push command. Push follows the same pattern as update but simpler: no conflict resolution, no dry-run (push is always real), filter to ahead submodules only.

  **RunE flow:**
  1. Parse flags: auto, verbose, jobs
  2. Get project root: `os.Getwd()`
  3. Create engine and context with cancel
  4. Scan submodules (same as update -- reuse scan pattern)
  5. Filter to submodules with StatusAhead only. If none: print "No submodules have unpushed commits." and return.

  **Auto mode / non-TTY:**
  - Push all ahead submodules
  - Stream results via OnProgress callback: checkmark + path + "pushed" or cross + path + error
  - Print summary: "N pushed, N failed"
  - Exit code: ExitError if any failed

  **Interactive mode:**
  - Same 3-phase pattern as update but simpler:
    - Phase A: Scan with progress (reuse pattern from update)
    - Phase B: TUI selector filtered to ahead submodules, title "Select submodules to push"
    - Phase C: Push selected with result streaming
  - After push: print summary banner

  **Engine.Push() stub:** Same approach as update -- check if Engine.Push() exists. If not, create a minimal stub: `func (e *Engine) Push(ctx context.Context, targets []*SubmoduleInfo, opts PushOpts) (*PushResult, error) { return nil, fmt.Errorf("not implemented: engine.Push (Phase 3 Plan 03)") }`. This will be replaced when Phase 3 Plan 03 runs.

  **Detached HEAD handling:** When streaming results, if a PushAction has "skipped" action due to detached HEAD, print a warning: "Skipped path (detached HEAD -- cannot push without a branch)"

  **Ctrl+C:** Same pattern as update -- signal handler cancels context, show partial results.

<task type="auto">

  <action>
  **internal/cli/exec.go -- exec command:**
  ```
  ssu exec <command> [args...]
  ```
  - `Use: "exec [command] [args...]"`, `Args: cobra.MinimumNArgs(1)`
  - RunE flow:
    1. Get project root, create engine
    2. Scan submodules (quick scan -- no need for full fetch, just enumerate paths)
       - For exec, we don't need to fetch. Just get submodule paths via engine.
       - Actually, do a full scan so we have status info for the TUI selector metadata display.
       - But if --auto, skip the TUI and run in all submodules.
    3. If auto or non-TTY: run command in all submodules
    4. If interactive: show TUI selector with ALL submodules (not filtered), title "Select submodules for: command"
    5. For each selected submodule path:
       - Print separator: "==> path"
       - Create `exec.CommandContext(ctx, args[0], args[1:]...)` with Dir = filepath.Join(rootDir, path)
       - Set cmd.Stdout = cmd.OutOrStdout(), cmd.Stderr = cmd.ErrOrStderr()
       - Run and capture error
       - If error: print error line but CONTINUE to next submodule (don't abort)
    6. After all: print summary "Ran in N submodule(s), N failed"
    7. Exit code: ExitError if any failed

  **internal/cli/init.go -- init wizard:**
  - `Use: "init"`, Short: "Initialize SSU configuration"
  - RunE flow (simple sequential prompts, NOT bubbletea -- per RESEARCH.md recommendation):
    1. Get project root
    2. Check if `.ssu.yaml` exists: if yes, print "Config already exists: .ssu.yaml" and return error
    3. Detect submodules: run engine scan or just `git submodule status` to count
       - Use `git.NewExecGit().SubmodulePaths(ctx, cwd)` to enumerate
    4. Print: "Found N submodule(s) in project."
    5. Prompt for parallel jobs: `fmt.Print("Parallel fetch jobs [8]: ")`, read from stdin, default to 8
    6. Prompt for branch priority: `fmt.Print("Branch priority [develop,master,main]: ")`, default to "develop,master,main"
    7. Prompt for skip list: `fmt.Print("Skip list (comma-separated, empty for none): ")`, default to empty
    8. Write `.ssu.yaml`:
       ```yaml
       git:
         parallel_jobs: 8
         branch_priority:
           - develop
           - master
           - main
         skip: []
       ```
    9. Print: "Created .ssu.yaml. Run `ssu status` to see your submodules."
  - Use `bufio.NewScanner(os.Stdin)` for input (same pattern as existing interactive menu)
  - If not a TTY: print error "ssu init requires a terminal" and return error

  **internal/cli/root.go -- register new subcommands:**
  - Add `NewExecCmd()` and `NewInitCmd()` to the `root.AddCommand(...)` call
  - Keep existing subcommands (status, update, push, rollback, backup, version, completion)
  - The `showInteractiveMenu` function: keep as-is for now (simple numbered menu). It works and replacing it with bubbletea is not in the locked decisions. Add "exec" and "init" as menu items (numbers 6 and 7, shifting help to 8).
    - Actually, the init command is one-time and exec is a power-user feature. Adding them to the interactive menu is optional. Add exec (it's useful), skip init (users run it directly). Add exec as option 6, keep help as 7, total 7 items.
