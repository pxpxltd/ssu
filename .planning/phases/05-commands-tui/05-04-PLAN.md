<task type="auto">
  <name>Task 2: Exec command with TUI selector and --auto mode</name>
  <files>internal/cli/exec.go</files>
  <action>
  **internal/cli/exec.go -- exec command:**
  ```
  ssu exec <command> [args...]
  ```
  - `Use: "exec [command] [args...]"`, `Args: cobra.MinimumNArgs(1)`
  - Add `--auto` flag (bool): when set, runs in all non-skipped submodules without TUI selection. This is consistent with how `--auto` works for update (selects ALL pending) and push (selects ALL ahead). For exec, `--auto` means "all non-skipped submodules."
  - RunE flow:
    1. Get project root, create engine
    2. Scan submodules (full scan so we have status info for the TUI selector metadata display)
    3. Exclude root from targets (exec only runs in submodules, not root)

    **Auto mode OR non-TTY:**
    - Run command in ALL non-skipped submodules (no TUI selection). This is the `--auto` semantics: select everything, skip prompts. Equivalent to selecting all in the TUI and confirming.

    **Interactive mode (TTY, not --auto):**
    - **LOCKED DECISION:** Show TUI selector with ALL non-skipped submodules (not filtered by status), title "Select submodules for: <command>"
    - User selects which submodules to run the command in
    - Confirmation step shows selected paths and the command to run

    4. For each target submodule path (sequential execution):
       - Print separator header: `"==> path"` (bold, using printer)
       - Create `exec.CommandContext(ctx, args[0], args[1:]...)` with `Dir = filepath.Join(rootDir, path)`
       - Set `cmd.Stdout = cmd.OutOrStdout()`, `cmd.Stderr = cmd.ErrOrStderr()`
       - Run and capture error
       - **Error handling:** On error, use `printer.Errorf("%s: command exited with status %d", path, exitCode)`. Extract exit code from `exec.ExitError` via type assertion: `var exitErr *exec.ExitError; if errors.As(err, &exitErr) { exitCode = exitErr.ExitCode() }`. Track failed paths in a `[]string` slice for the summary count.
       - On success: no extra output (the command's own stdout is already printed)
       - CONTINUE to next submodule on error (don't abort unless Ctrl+C)
    5. After all: print summary `"Ran in N submodule(s), N failed"` (only print the failed part if N > 0)
    6. Exit code: ExitError if any failed, ExitSuccess if all succeeded
  </action>
  <verify>
  `go build ./...` compiles.
  `go vet ./internal/cli/...` clean.
  `go run . exec echo hello` shows TUI selector (interactive) or runs in all submodules (if piped/--auto).
  `go run . exec --auto echo hello` runs in all submodules without prompts.
  </verify>
  <done>
  `ssu exec <cmd>` interactive mode: TUI selector for submodule selection, then runs command in each selected submodule with per-submodule output headers.
  `ssu exec --auto <cmd>` runs in all non-skipped submodules without prompts (consistent --auto semantics).
  Failed commands tracked with exit code, summary printed at end.
  </done>
</task>
