  **Branch: dry-run mode** (simplest path, no TUI needed):
  - Run `eng.Scan(ctx, scanOpts)` synchronously (no progress bar needed for dry-run)
  - Filter submodules to only those with StatusPending
  - If none: print "All submodules are up to date." and return
  - For each pending submodule, retrieve its current SHA by calling `e.git.CurrentSHA(ctx, filepath.Join(rootDir, sub.Path))` where `e` is the engine's git service. Since the engine's git field is unexported, either:
    (a) Add a helper method on Engine: `func (e *Engine) GitCurrentSHA(ctx context.Context, dir string) (string, error)` that delegates to `e.git.CurrentSHA()`, OR
    (b) Create a separate `git.NewExecGit()` instance in the command to call CurrentSHA directly.
    Prefer option (b) -- create `gitSvc := git.NewExecGit()` at the top of RunE alongside the engine, reuse it for SHA lookups.
  - For target SHA: derive from the remote ref. Call `gitSvc.CurrentSHA(ctx, filepath.Join(rootDir, sub.Path))` for current, and for target SHA use: `git rev-parse origin/<targetBranch>` via a raw git call, or use `gitSvc.CurrentSHA` after noting that the target ref is `origin/<sub.TargetBranch>`. Actually, the simplest approach: shell out with ExecGit to get `rev-parse --short origin/<targetBranch>` for the target. The GitService interface does not have a "resolve ref to SHA" method, so use ExecGit's underlying exec: create a small helper `resolveRef(ctx, dir, ref string) string` that runs `git rev-parse --short <ref>` and returns the 7-char prefix, or "unknown" on error.
  - **LOCKED DECISION -- dry-run table columns:** Print a diff table using lipgloss/table with these exact headers:
    - "Path", "Current SHA", "Target SHA", "Behind"
  - One row per pending submodule:
    - Path: sub.Path
    - Current SHA: 7-char prefix from gitSvc.CurrentSHA(ctx, subDir) -- truncate to 7 chars with `sha[:7]`
    - Target SHA: 7-char prefix from resolveRef(ctx, subDir, "origin/"+sub.TargetBranch) -- truncate to 7 chars
    - Behind: strconv.Itoa(sub.CommitsBehind)
  - Print footer: "N submodule(s) would be updated (dry-run)"
  - Return nil (exit 0)

  **Branch: interactive TUI mode** (TTY, not auto, not dry-run):
  This is the complex path. Three phases: scan with progress, select with TUI, update with streaming.

  **Phase A: Scan with progress bar**
  - Create ProgressModel: `progModel := tui.NewProgressModel(0)` (total unknown until scan starts -- will get updated)
  - Create tea.Program: `p := tea.NewProgram(progModel)` -- NO alt-screen (inline rendering per RESEARCH.md recommendation)
  - During Phase A, bubbletea handles Ctrl+C via its default signal interceptor. Ensure `tea.Program` cleanup restores cursor/terminal state. This happens automatically when `p.Run()` returns -- bubbletea calls its `shutdown()` method which restores terminal settings. No extra cleanup needed here beyond `defer cancel()` on the context.
  - Start scan in goroutine, sending progress via p.Send():
    ```go
    go func() {
        scanOpts.OnProgress = func(evt engine.ProgressEvent) {
            p.Send(tui.FetchProgressMsg{
                Path:  evt.Path,
                Done:  evt.Done,
                Total: evt.Total,
            })
        }
        result, err := eng.Scan(ctx, scanOpts)
        p.Send(tui.FetchCompleteMsg{Result: result, Err: err})
    }()
    ```
  - Run `p.Run()` -- blocks until FetchCompleteMsg arrives
  - Extract result from final model. If error, return it.
  - Filter to pending submodules. If none: print "All submodules are up to date." return.

  **Phase B: Select submodules with TUI selector**
  - Create SubmoduleItem slice from pending submodules
  - Create SelectorModel: `selModel := tui.NewSelectorModel(items, tui.SelectorOpts{Title: "Select submodules to update", ShowDetail: true})`
  - Create tea.Program: `p2 := tea.NewProgram(selModel)` -- inline mode
  - During Phase B, bubbletea handles Ctrl+C the same way. When `p2.Run()` returns after Ctrl+C, the SelectorModel.Cancelled() will be true. Bubbletea restores terminal state automatically.
  - Run `p2.Run()` -- blocks until user confirms or cancels
  - Extract from final model: if cancelled, print "Cancelled." and return nil
  - Get selected items: `targets := selModel.Selected()`
  - If no targets (shouldn't happen if confirm requires >0), return nil

  **Phase C: Update with result streaming**
  - Print "Updating N submodule(s)..."
  - Set up updateOpts with progress callback for streaming results:

    ```
    printer := output.NewPrinter(cmd.OutOrStdout())
    updateOpts.OnProgress = func(evt engine.ProgressEvent) {
        switch evt.Type {

        case engine.EventFailed:
            printer.Errorf("%s: %v", evt.Path, evt.Error)
        }
    }
    ```
  - Call `eng.Update(ctx, targets, updateOpts)`
  - If ctx was cancelled (Ctrl+C): print partial results banner

  - Print final summary banner: "N updated, N skipped, N conflicts"
  - For each action with ConflictHint: print actionable hint with `printer.Warning(action.ConflictHint)`
  - Exit code: ExitConflict if any conflicts, ExitError if any errors, ExitSuccess otherwise

  **Ctrl+C handling:**
  - `context.WithCancel` is wired through. When Ctrl+C is detected by bubbletea (during Phase A or B), the program returns and the context gets cancelled via defer.
  - During Phase C (no bubbletea running), set up a signal handler:
