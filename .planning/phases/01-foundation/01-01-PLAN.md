<task type="auto">
  <name>Task 1: Go module init, dependencies, project structure, and Makefile</name>
  <files>
    go.mod
    go.sum
    Makefile
    legacy/ssu
  </files>
  <action>
    1. Initialize Go module:
       ```
       go mod init github.com/pxpxltd/ssu
       ```
       Set minimum Go version to 1.21 in go.mod.

    2. Install dependencies:
       ```
       go get github.com/spf13/cobra@v1.10.2
       go get github.com/fatih/color@v1.18.0
       ```
       pflag and go-isatty are pulled in transitively -- do NOT explicitly `go get` them.

    3. Move the bash script to legacy:
       ```
       mkdir -p legacy
       git mv ssu legacy/ssu
       ```
       This preserves git history. The Go binary will own `ssu` as the build output name.

    4. Create `Makefile` with these targets:
       - `build`: `go build -ldflags "$(LDFLAGS)" -o ssu ./cmd/ssu`
         LDFLAGS should inject `-X main.version=$(VERSION) -X main.commit=$(COMMIT) -X main.date=$(DATE)` with `-s -w` for stripping.
         VERSION from `git describe --tags --always --dirty`, COMMIT from `git rev-parse --short HEAD`, DATE from `date -u`.
       - `test`: `go test ./...`
       - `lint`: `golangci-lint run`
       - `clean`: `rm -f ssu`
       - Mark all targets as `.PHONY`

    5. Run `go mod tidy` to clean up go.sum.
  </action>
  <verify>
    - `cat go.mod` shows module path `github.com/pxpxltd/ssu` and Go 1.21+
    - `ls legacy/ssu` confirms bash script moved
    - `cat Makefile` shows build/test/lint/clean targets
    - `go mod tidy` exits 0
  </verify>
  <done>Go module initialized with cobra + fatih/color deps, bash script moved to legacy/, Makefile ready with ldflags injection</done>
</task>

<task type="auto">
  <name>Task 2: Output utilities (color, symbols, printer) and cobra CLI skeleton</name>
  <files>
    internal/cli/output/color.go
    internal/cli/output/symbols.go
    internal/cli/output/printer.go
    internal/cli/root.go
    internal/cli/status.go
    internal/cli/update.go
    internal/cli/push.go
    internal/cli/rollback.go
    internal/cli/backup.go
    cmd/ssu/main.go
  </files>
  <action>
    **Output package (`internal/cli/output/`):**

    1. `color.go`: Define pre-configured color objects using `fatih/color`:
       - General: `Success` (green), `Error` (red), `Warning` (yellow), `Info` (cyan), `Muted` (hi-black/gray), `Bold`
       - Status-specific: `Pending` (green), `Current` (cyan), `Modified` (yellow), `Ahead` (magenta), `Conflict` (red)
       - `IsColorEnabled() bool` -- returns `!color.NoColor`
       - `IsTTY() bool` -- check using `mattn/go-isatty` on `os.Stdout.Fd()`, not just `color.NoColor` (a pipe with NO_COLOR unset should still detect non-TTY)
       - `ForceDisableColor()` -- sets `color.NoColor = true`
       - Do NOT add custom NO_COLOR logic -- fatih/color handles it. The only function of this package is to centralize color definitions.

    2. `symbols.go`: Define Unicode symbol constants:
       - `Check = "✓"`, `Cross = "✗"`, `Arrow = "→"`, `Bullet = "●"`, `Pipe = "│"`, `Ellipsis = "…"`
       - These are string constants, not colored -- callers apply color via the output package.

    3. `printer.go`: Create a `Printer` struct that wraps an `io.Writer`:
       - `NewPrinter(w io.Writer) *Printer`
       - Methods: `Success(msg string)`, `Error(msg string)`, `Warning(msg string)`, `Info(msg string)`
       - Each method prints the appropriate symbol + colored message. Example: `Success("Updated plugins/foo")` prints `✓ Updated plugins/foo` in green.
       - Also: `Successf`, `Errorf`, `Warningf`, `Infof` variants with `fmt.Sprintf` formatting.
       - The printer respects whatever color state fatih/color is in (NO_COLOR, TTY detection happen at the fatih/color level, not here).

    **CLI skeleton (`internal/cli/`):**

    4. `root.go`: Create `NewRootCmd(version, commit, date string) *cobra.Command`:
       - Use: "ssu", Short: "Smart Submodule Updater"
       - Long description explaining SSU's purpose
       - `SilenceUsage: true`, `SilenceErrors: true`
       - Global persistent flags: `-v/--verbose` (bool), `-n/--dry-run` (bool), `-a/--auto` (bool), `-j/--jobs` (int, default 8)
       - Add all subcommands via `root.AddCommand(...)`: status, update, push, rollback, backup (stubs from this task), plus version and completion (added in Plan 02)
       - For the root command's `RunE`: when run with no subcommand in a TTY, show a simple interactive numbered menu listing the 6 actions (status, update, push, rollback, backup, help). Read a single line from stdin, dispatch to the chosen subcommand by calling `root.SetArgs([]string{"chosen"})` then `root.Execute()`. When not a TTY, just call `cmd.Help()`. Keep the menu implementation simple -- this is Phase 1, Bubble Tea replaces it in Phase 5.
       - Do NOT use PersistentPreRunE for git context checks (see Research pitfall 4). That comes in later phases.

    5. Subcommand stubs -- each in its own file, each exports `New<Name>Cmd() *cobra.Command`:
       - `status.go`: Use "status", Short "Show submodule status". RunE prints "status: not implemented yet" via cmd.Println and returns nil. Add `--json` bool flag (for future use).
       - `update.go`: Use "update", Short "Update submodules". RunE prints "update: not implemented yet". Flags will be added in Phase 5.
       - `push.go`: Use "push", Short "Push ahead submodules". RunE prints "push: not implemented yet".
       - `rollback.go`: Use "rollback", Short "Rollback from backup". RunE prints "rollback: not implemented yet". Takes optional positional arg (backup file).
       - `backup.go`: Use "backup", Short "Manage backups". RunE prints "backup: not implemented yet". Will get subcommands (list, clean) in Phase 4.

    6. `cmd/ssu/main.go`: Entry point:
       - Declare `var version, commit, date string` with defaults "dev", "unknown", "unknown"
       - In `main()`: if `version == "dev"`, attempt `debug.ReadBuildInfo()` fallback to populate commit (first 7 chars of vcs.revision), date (vcs.time), and dirty flag (vcs.modified appends "-dirty" to commit).
       - Create root command via `cli.NewRootCmd(version, commit, date)`
       - Call `root.Execute()`, on error print to stderr and `os.Exit(1)`
       - NOTE: Do NOT wire compat check or version/completion commands yet -- that is Plan 02's job. Just wire the 5 stubs + root for now, so the binary compiles and runs.

    7. Verify the binary builds and runs:
       ```
       go build ./cmd/ssu
       ./ssu --help
       ./ssu status
       ```
  </action>
  <verify>
    - `go build ./cmd/ssu` succeeds with no errors
    - `./ssu --help` shows all subcommands (status, update, push, rollback, backup)
    - `./ssu status` prints "status: not implemented yet"
    - `go vet ./...` passes
    - `NO_COLOR=1 go run ./cmd/ssu --help` works (colors disabled)
    - `make build` produces a binary with injected version info: `./ssu version` -- this will fail since version cmd isn't wired yet, but `go build` should succeed
  </verify>
  <done>Binary compiles and runs. `ssu --help` lists all subcommands. Stub commands print "not implemented yet". Output utilities provide color-aware printing with NO_COLOR/TTY support. Interactive root menu shows numbered options in TTY mode.</done>
