  <name>Task 1: Push method with parallel orchestration and detached HEAD handling</name>
  <files>internal/engine/push.go</files>
  <action>
Create `internal/engine/push.go` implementing:

```go
func (e *Engine) Push(ctx context.Context, targets []*SubmoduleInfo, opts PushOpts) (*PushResult, error)
```

Add `RootDir string` to `PushOpts` (same pattern as UpdateOpts).

The `targets` parameter is the subset of scan.Submodules the user selected for push (filtered by Phase 5 TUI or --auto mode). The engine does NOT decide what to push -- the caller does.

Implementation:

a. Apply defaults: if opts.Concurrency <= 0, use runtime.NumCPU().

b. Filter targets: skip any SubmoduleInfo where IsRoot==true (root is display-only, never pushed by engine).

c. Use `var g errgroup.Group` with `g.SetLimit(opts.Concurrency)`. For each target:
   - Capture loop variable: `info := info`
   - Fire EventStarted progress event
   - Call `e.pushOne(ctx, opts.RootDir, info)` (helper method)
   - Append PushAction result to mutex-protected slice
   - Fire EventCompleted or EventFailed
   - Return nil to errgroup (continue-on-error)

d. `pushOne` helper:

```go
func (e *Engine) pushOne(ctx context.Context, rootDir string, info *SubmoduleInfo) PushAction
```

Logic:
1. Build `dir = filepath.Join(rootDir, info.Path)`
2. **Check detached HEAD**: if `info.DetachedHead` is true, return PushAction with Action="skipped (detached HEAD)", no error (this is expected behavior, not an error)
3. **Push**: Call `e.git.Push(ctx, dir, git.PushOpts{})` -- the ExecGit.Push implementation already handles:
   - Auto-detecting missing tracking branch and using -u flag
   - Detecting current branch for the push
   - So the engine just calls Push with empty opts (defaults to origin + current branch)
4. On success: PushAction with Branch=result.Branch, Action="pushed" (or "set up tracking + pushed" if result.NewTracking is true)
5. On failure: PushAction with Error=err, Action="push failed"
