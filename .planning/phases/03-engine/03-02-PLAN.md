  <action>
Create `internal/engine/update.go` implementing:

```go
func (e *Engine) Update(ctx context.Context, scan *ScanResult, targets []*SubmoduleInfo, opts UpdateOpts) (*UpdateResult, error)
```

The `targets` parameter is the subset of scan.Submodules the user selected for update (in Phase 5, the TUI selector filters this; for --auto mode, it is all pending submodules). This separation means the engine does NOT decide what to update -- the caller does.

Implementation:

a. Apply defaults: if opts.Concurrency <= 0, use runtime.NumCPU().

b. Filter targets: skip any SubmoduleInfo where IsRoot==true, or Statuses only contains StatusCurrent/StatusMissing/StatusSkipped. These are not updateable.

c. Use `var g errgroup.Group` with `g.SetLimit(opts.Concurrency)` for parallel processing. For each target:
   - Capture loop variable: `info := info` (Go 1.21)
   - Fire EventStarted progress event
   - Call `e.updateOne(ctx, scan.RootDir(), info)` (helper method, see below)
   - Append UpdateAction result to mutex-protected slice
   - Fire EventCompleted or EventFailed progress event
   - Return nil to errgroup (continue-on-error)

d. Note: `scan.RootDir()` -- add a helper method on ScanResult or pass rootDir through UpdateOpts. Simpler: add `RootDir string` field to ScanResult (populated during Scan from opts.RootDir). Or accept rootDir as a parameter on Update. Choose the cleanest: add RootDir to UpdateOpts.

Actually, cleaner: add `RootDir string` to `UpdateOpts` (caller knows where the project is). This avoids coupling Update to ScanResult's internal structure.

Revise signature:
```go
func (e *Engine) Update(ctx context.Context, targets []*SubmoduleInfo, opts UpdateOpts) (*UpdateResult, error)
```

And add `RootDir string` to `UpdateOpts`.

e. `updateOne` helper method processes a single submodule:

```go
func (e *Engine) updateOne(ctx context.Context, rootDir string, info *SubmoduleInfo) UpdateAction
```

Logic for `updateOne`:
1. Record `BeforeStatus = info.Statuses`
2. Build `dir = filepath.Join(rootDir, info.Path)` and `remoteRef = "origin/" + info.TargetBranch`
3. **If submodule has local changes** (`info.HasChanges` is true):
   - Execute 3-step conflict resolution:
     a. `e.git.Stash(ctx, dir)` -- stash local changes
     b. If stash fails, record error and return with Action "stash failed"
     c. `e.git.Merge(ctx, dir, remoteRef)` -- attempt merge on clean state
     d. If merge succeeds: `e.git.StashPop(ctx, dir)` -- reapply stash
        - If stash pop fails: Action "merged but stash pop failed" (warn, not fatal)
        - If stash pop succeeds: Action "stashed, merged N commits, restored changes"
     e. If merge fails with conflict:
        - `e.git.MergeAbort(ctx, dir)` -- abort the failed merge
        - `e.git.StashPop(ctx, dir)` -- restore original stash (check abort succeeded first)
        - Build ConflictHint: `fmt.Sprintf("cd %s && git stash && git merge %s && git stash pop", info.Path, remoteRef)`
        - Record StatusConflict in AfterStatus, Action "conflict after stash+retry"
     f. If merge fails without conflict (other error): abort, restore stash, record error
4. **If submodule is clean** (no local changes, just behind):
   - `e.git.Merge(ctx, dir, remoteRef)` -- direct merge
   - If merge succeeds: Action "merged N commits" (N = info.CommitsBehind)
   - If merge fails with conflict: ConflictHint with manual resolution commands
   - If merge fails otherwise: record error
5. After update, re-detect status to populate AfterStatus:
   - Check HasLocalChanges, CommitsBehind, CommitsAhead to compute new status set
   - Or simplify: if merge succeeded, set AfterStatus to [StatusCurrent]; if conflict, [StatusConflict]; if error, [StatusError]

Keep the re-detection simple for now: if merge succeeded without issues, AfterStatus = [StatusCurrent]. If conflict, [StatusConflict]. If error, [StatusError]. Phase 5 can do a fresh scan for display.
