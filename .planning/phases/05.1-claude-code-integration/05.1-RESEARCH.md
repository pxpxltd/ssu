# Phase 5.1: Claude Code Integration - Research

**Researched:** 2026-02-09
**Domain:** Claude Code skills/commands system, Go embed, CLI installer subcommand
**Confidence:** HIGH

## Summary

This phase adds Claude Code integration to SSU so that Claude Code sessions can manage git submodules through SSU instead of raw `git submodule` commands. The deliverables are: (1) slash command files that Claude Code users can invoke as `/ssu:status`, `/ssu:update`, `/ssu:push`, (2) a CLAUDE.md snippet that teaches Claude Code when and how to use SSU, and (3) an `ssu claude install` CLI command that copies these files to `~/.claude/commands/` for global availability.

Claude Code's custom command system is well-documented and stable. Commands are markdown files with YAML frontmatter placed in `.claude/commands/` (project-scope) or `~/.claude/commands/` (user-scope). The newer "skills" system (`.claude/skills/<name>/SKILL.md`) supersedes commands but commands still work identically. For SSU's use case, the simpler `.claude/commands/` approach is sufficient since we need no supporting files, scripts, or templates.

The Go implementation uses `//go:embed` to bundle the markdown command files and CLAUDE.md snippet into the binary. The `ssu claude install` command reads embedded files and writes them to `~/.claude/commands/ssu/`. This is a standard Go pattern -- embed at build time, extract at runtime to the user's home directory.

**Primary recommendation:** Use `.claude/commands/ssu/` namespace (not skills) for simplicity. Embed command markdown files via `//go:embed`. The `ssu claude install` command writes embedded content to `~/.claude/commands/ssu/` with overwrite confirmation. All SSU commands invoked from Claude Code MUST use `--auto` flag since Claude Code's Bash tool runs without a TTY.

## Architecture Patterns

### Recommended Project Structure
```
internal/
├── claude/                  # New package for Claude Code integration
│   ├── commands/            # Embedded command markdown files (source)
│   │   ├── status.md        # /ssu:status command
│   │   ├── update.md        # /ssu:update command
│   │   └── push.md          # /ssu:push command
│   ├── snippet.md           # Embedded CLAUDE.md snippet (source)
│   ├── embed.go             # //go:embed directives and FS variable
│   └── install.go           # Install logic: write files to ~/.claude/
├── cli/
│   └── claude.go            # NewClaudeCmd() cobra command: `ssu claude install`
```

### Pattern 1: Embed + Extract
**What:** Bundle static markdown files into the Go binary using `//go:embed`, extract them to the filesystem on `ssu claude install`.
**When to use:** Whenever a CLI tool needs to install configuration/template files to the user's system.
**Example:**
```go
// Source: https://pkg.go.dev/embed
package claude

import "embed"

//go:embed commands/*.md
var CommandsFS embed.FS

//go:embed snippet.md
var SnippetContent string
```

### Pattern 2: Namespace-Prefixed Commands
**What:** Place command files in a subdirectory (`ssu/`) under `~/.claude/commands/` so they appear as `/ssu:status`, `/ssu:update`, `/ssu:push` in Claude Code.
**When to use:** When a tool provides multiple related slash commands that should be namespaced.
**Example:**
```
~/.claude/commands/
└── ssu/
    ├── status.md     # becomes /ssu:status
    ├── update.md     # becomes /ssu:update
    └── push.md       # becomes /ssu:push
```

Claude Code's naming convention: directory name becomes the prefix, filename (minus .md) becomes the suffix, joined by `:`. This is confirmed by examining existing commands like `/gsd:execute-phase` which lives at `~/.claude/commands/gsd/execute-phase.md`.

### Pattern 3: Non-TTY Aware Commands
**What:** All slash commands that invoke SSU must use `--auto` mode because Claude Code's Bash tool does NOT provide a TTY. Interactive TUI selection is impossible.
**When to use:** Any command that shells out to an interactive CLI from within Claude Code.
**Example:**
```markdown
---
name: ssu:update
description: Update git submodules using SSU
allowed-tools:
  - Bash
---

Run SSU to update submodules in automatic mode:

`ssu update --auto`

$ARGUMENTS
```

### Pattern 4: CLAUDE.md Snippet Generation
**What:** `ssu claude snippet` outputs a markdown block that users can paste into their project's CLAUDE.md. This teaches Claude Code about SSU's capabilities.
**When to use:** For tools that want to inject domain knowledge into Claude Code's context.
**Example:**
```go
// claude.go - snippet subcommand
func NewClaudeSnippetCmd() *cobra.Command {
    return &cobra.Command{
        Use:   "snippet",
        Short: "Print CLAUDE.md snippet for SSU",
        RunE: func(cmd *cobra.Command, args []string) error {
            fmt.Fprint(cmd.OutOrStdout(), claude.SnippetContent)
            return nil
        },
    }
}
```

### Anti-Patterns to Avoid
- **Interactive prompts in slash commands:** Claude Code's Bash tool has no TTY. Never omit `--auto` when invoking SSU from a slash command.
- **Hardcoding paths:** Always use `os.UserHomeDir()` to resolve `~`. Do not hardcode `/home/user/`.
- **Overwriting without warning:** `ssu claude install` should detect existing files and ask for confirmation (or use `--force` flag) to avoid destroying user customizations.
- **Giant CLAUDE.md snippets:** Keep the snippet focused (under 100 lines). Claude Code loads CLAUDE.md into every conversation context; bloat wastes tokens.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Embedding static files | Custom asset pipeline | `//go:embed` directive | Stdlib, compile-time verified, zero overhead |
| Home directory resolution | Manual `$HOME` parsing | `os.UserHomeDir()` | Cross-platform (Linux, macOS, Windows) |
| Walking embedded files | Manual file listing | `fs.WalkDir` on `embed.FS` | Handles nested dirs, stdlib |
| YAML frontmatter in markdown | Custom parser | Hardcoded frontmatter in source files | Frontmatter is static, no need to parse at runtime |

**Key insight:** The command files are static markdown -- they are authored once and embedded. There is no need for runtime templating or dynamic generation of the command files themselves. The only dynamic part is the CLAUDE.md snippet (which could include the SSU version).

## Common Pitfalls

### Pitfall 1: Claude Code Bash Tool Has No TTY
**What goes wrong:** Slash commands invoke `ssu update` without `--auto`, causing SSU to attempt TUI rendering or prompt for input, which hangs or errors.
**Why it happens:** Developers test commands from their terminal (which has a TTY) but Claude Code's Bash tool uses `subprocess.Popen` with pipes (no TTY).
**How to avoid:** Every slash command that runs SSU must include `--auto` flag. The CLAUDE.md snippet should also instruct Claude to always use `--auto`.
**Warning signs:** Commands hang indefinitely when invoked from Claude Code.

### Pitfall 2: Overwriting User Customizations
**What goes wrong:** `ssu claude install` blindly overwrites files in `~/.claude/commands/ssu/`, destroying user modifications.
**Why it happens:** The install command uses simple file writes without checking for existing files.
**How to avoid:** Check if files exist, compare content, and either skip unchanged files or require `--force` to overwrite modified files.
**Warning signs:** Users report losing customizations after running `ssu claude install` to upgrade.

### Pitfall 3: Slash Command Name Conflicts with Skills
**What goes wrong:** If a user has `.claude/skills/ssu/SKILL.md`, it takes precedence over `.claude/commands/ssu/status.md`.
**Why it happens:** Claude Code's priority: enterprise > personal skills > project skills > commands.
**How to avoid:** Document this clearly. The `install` command could detect conflicts and warn.
**Warning signs:** Commands don't work despite being installed.

### Pitfall 4: Embed Directive Excludes Dot Files
**What goes wrong:** Files starting with `.` or `_` in the embedded directory are silently excluded.
**Why it happens:** Go's embed system excludes hidden files by default.
**How to avoid:** Don't name embedded files with `.` or `_` prefix. Use `all:` prefix if needed. For SSU's case, command files are named `status.md`, `update.md`, `push.md` -- no issue.
**Warning signs:** Missing files at runtime despite being in source directory.

### Pitfall 5: Missing `ssu` Binary in PATH
**What goes wrong:** Slash commands invoke `ssu` but the binary is not installed or not in Claude Code's PATH.
**Why it happens:** User installed commands via `ssu claude install` but later removed or relocated the `ssu` binary.
**How to avoid:** Slash commands should include a preamble that checks for `ssu` in PATH and gives a helpful error. Alternatively, use absolute path from `which ssu` at install time.
**Warning signs:** "command not found: ssu" errors in Claude Code.

## Code Examples

### Embedded File Structure
```go
// internal/claude/embed.go
package claude

import "embed"

// CommandsFS contains the slash command markdown files.
//
//go:embed commands/*.md
var CommandsFS embed.FS

// SnippetContent contains the CLAUDE.md snippet text.
//
//go:embed snippet.md
var SnippetContent string
```

### Install Logic
```go
// internal/claude/install.go
package claude

import (
    "fmt"
    "io/fs"
    "os"
    "path/filepath"
)

// InstallCommands copies embedded slash command files to ~/.claude/commands/ssu/.
func InstallCommands(force bool) error {
    home, err := os.UserHomeDir()
    if err != nil {
        return fmt.Errorf("cannot determine home directory: %w", err)
    }

    targetDir := filepath.Join(home, ".claude", "commands", "ssu")
    if err := os.MkdirAll(targetDir, 0o755); err != nil {
        return fmt.Errorf("cannot create directory %s: %w", targetDir, err)
    }

    return fs.WalkDir(CommandsFS, "commands", func(path string, d fs.DirEntry, err error) error {
        if err != nil || d.IsDir() {
            return err
        }

        content, err := CommandsFS.ReadFile(path)
        if err != nil {
            return err
        }

        // Strip the "commands/" prefix to get just the filename
        name := filepath.Base(path)
        dest := filepath.Join(targetDir, name)

        // Check for existing file
        if !force {
            if existing, err := os.ReadFile(dest); err == nil {
                if string(existing) == string(content) {
                    return nil // identical, skip
                }
                return fmt.Errorf("file %s already exists and differs (use --force to overwrite)", dest)
            }
        }

        return os.WriteFile(dest, content, 0o644)
    })
}
```

### CLAUDE.md Snippet Content
```markdown
## SSU - Smart Submodule Updater

This project uses SSU for git submodule management. When working with submodules, prefer SSU commands over raw git submodule commands.

**Available commands:**
- `ssu status` - Show status of all submodules (use `--json` for machine-readable output)
- `ssu update --auto` - Update all pending submodules (MUST use --auto in non-interactive contexts)
- `ssu push --auto` - Push all ahead submodules (MUST use --auto in non-interactive contexts)
- `ssu update --auto --dry-run` - Preview what would change without modifying anything

**When to use SSU instead of raw git:**
- Checking submodule status: `ssu status` instead of `git submodule status`
- Updating submodules: `ssu update --auto` instead of `git submodule update --remote`
- Pushing submodule changes: `ssu push --auto` instead of manually cd-ing into each submodule

**Important:**
- Always use `--auto` flag when running SSU from scripts or non-interactive contexts
- SSU creates automatic backups before updates (rollback with `ssu rollback`)
- SSU handles merge conflicts automatically (stash, merge, restore)
```

**Current state for SSU:**

- If SSU later needs supporting files (scripts, templates), migrating from commands to skills is trivial (same frontmatter, just move to skills directory)

**Deprecated/outdated:**
- Nothing relevant is deprecated. The commands system is explicitly maintained alongside skills.

## Open Questions

1. **Should `ssu claude install` also write the CLAUDE.md snippet?**
   - What we know: The snippet is useful but CLAUDE.md is user-managed; auto-appending could corrupt it
   - What's unclear: Whether users want auto-append or just stdout printing
   - Recommendation: `ssu claude install` installs commands only. `ssu claude snippet` prints the snippet to stdout for manual copy-paste. A `--append` flag on snippet could append to `./CLAUDE.md` if explicitly requested.

2. **Should we target the `ssu-skills` repo as a distributable plugin?**
   - What we know: An empty git repo `ssu-skills/` exists in the project; Claude Code supports plugin distribution
   - What's unclear: Plugin packaging requirements, whether this is Phase 5.1 scope
   - Recommendation: Out of scope for Phase 5.1. The `ssu-skills` repo can be populated later as a Phase 6 or post-launch task.

3. **Should commands check for `ssu` binary availability?**
   - What we know: If `ssu` is not in PATH, commands will fail with unhelpful errors
   - What's unclear: Whether the overhead of a `which ssu` check is worth the complexity
   - Recommendation: Include a brief `which ssu || echo "SSU not found"` preamble in each command using `!` backtick syntax for dynamic context injection. LOW priority -- most users who install commands already have `ssu`.
